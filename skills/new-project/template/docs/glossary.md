# Glossary

Each project term is defined once, here. Docs link to this table instead of redefining terms. Add a row the first time a new term appears, and keep the table sorted A–Z.

| Term | Meaning | See also |
|---|---|---|
| Brief | A one-page, plain-language summary for the team head, in `docs/briefs/`. | status-brief skill |
| Charter | `docs/charter.md`: why the project exists, its goals, success criteria and scope. | [charter.md](charter.md) |
| Concept doc | A general explanation of an idea the project relies on, in `docs/concepts/`. | deep-doc skill |
| Decision (D-nnn) | An entry in `docs/decisions.md`, numbered D-001 and up. | [decisions.md](decisions.md) |
| Handoff | `session/HANDOFF.md`: the working state, written for the next session. | handoff skill |
| Input | A document the team gave us, kept read-only in `inputs/`. | `inputs/README.md` |
| Lesson (L-nnn) | An entry in `docs/learnings.md`, numbered L-001 and up. | [learnings.md](learnings.md) |
| Plan | A step-by-step plan for one feature, written before coding, in `session/plans/`. | `session/plans/README.md` |
| Story | `docs/story.md`: the project's narrative and reading guide, written at the end. | [story.md](story.md) |
| Task (T-nnn) | An item in `docs/tracker.md`, numbered T-001 and up, never reused. | [tracker.md](tracker.md) |
